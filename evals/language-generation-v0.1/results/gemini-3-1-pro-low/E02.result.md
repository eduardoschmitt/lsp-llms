## Post-run analysis (evaluator investigation, 2026-09-23 and later)

Model failure stands: YES — E02 remains FAIL at COMPILE. The benchmark
measures whether generated code works, so the result is not pardoned. But the
causal analysis cannot attribute the error to the model alone.

### Official Senior evidence

Senior support article 23581 — `Indexando fora dos limites`
(`https://suporte.senior.com.br/hc/pt-br/articles/4408650652436-23581-Mensagem-de-Indexando-fora-dos-limites`):

- Problem: running a report returns `Indexando fora dos limites`.
- Root cause per Senior: a vector-like list is used in a report and the record
  count overflows the indexed limit.
- Decisive example: `Definir Alfa xTexto[2];` with `xTexto[1]` / `xTexto[2]`
  does NOT create two variables called `xTexto` acting as a list — it creates
  a single Alfa with 2 positions of the char vector composing the Alfa
  (e.g. `xTexto[1]` is `T`, `xTexto[2]` is `e`, … accessed 1-based).
- Senior recommendation for collection-like needs: use a dynamic list
  (`Lista Dinâmica`), not bracket syntax.

This is deeper than "arrays start at 1": for `Alfa[N]`, brackets are not a
collection at all. (Whether the same holds for `Numero[N]` — the form the
model generated — remains open; the runtime rejected index 0 with
`Erro indexando fora dos limites: 0`.)

### Our own case notes share the blame

The frozen E02 evaluator notes told the grader that "if arrays are used, the
documented arrays-section pattern applies (0-based demonstrated use)". In
effect, our own material presented 0-based indexing as the valid pattern. The
model then did exactly the plausible thing with the knowledge provided —
generalizing `Definir Numero vnNotas[5]` + `vnNotas[0]` from C/Java/JS array
semantics — and the real Senior runtime rejected it.

So this was not "the model failed an index". It was: documentation → model
inferred a rule → coherent-looking code → real Senior rejection → corpus
gap/conflict surfaced. That is precisely what this evaluation was built to
detect, and it validates the project approach:

```text
llms-full.txt → Gemini → Definir Numero vnNotas[5] + vnNotas[0]
→ real Senior → FAIL (out-of-bounds at index 0)
```
